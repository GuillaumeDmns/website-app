# CLAUDE.md

Flutter mobility app for Île-de-France public transport, Citymapper-like: nearby real-time departures, search, stops, lines, journeys, favorites, traffic info. It must work on Android (main target), iOS, web and desktop (Linux, macOS, Windows). Rewritten from scratch in 2026 (the previous prototype is in git history, branch `temp`).

## Commands

```bash
flutter pub get
dart run build_runner build      # freezed / json_serializable (generated *.freezed.dart / *.g.dart are not committed)
flutter analyze
flutter run -d <linux|chrome|device-id> --dart-define=API_BASE_URL=http://localhost:8080
```

- `API_BASE_URL` defaults to production (`https://guillaumedamiens.com`). Android device on a local backend: `adb reverse tcp:8080 tcp:8080` then `http://localhost:8080`.
- `--dart-define=DEV_USERNAME=… --dart-define=DEV_PASSWORD=…`: signs in automatically (not in release builds).
- The router keeps the requested page in `from` through the splash and sign-in pages, so deep links survive signing in.
- `--route` is ignored on Linux desktop; on the web the routes are real URLs (`/stops/IDFM:71264`, `/lines/C01743`).

## Architecture (`lib/`)

- `main.dart`: path URL strategy, `ProviderScope`. `app/`: `app.dart` (`MaterialApp.router`, locale from `localeProvider`, light/dark from the system), `theme.dart` (`AppTheme`), `routes.dart` (paths), `router.dart` (go_router: auth redirect via `refreshListenable`, `ShellRoute` for the map pages), `shell.dart` (`AppShell`).
- **Layout**: `AppShell` puts the page in a side panel next to the map from 840 px wide, in a `DraggableScrollableSheet` over the map below. Pages use `PanelScrollScope.of(context)` as the controller of their main scroll view (null in the wide layout, and for pages not on top). The sheet's sizes come from the page (`_SheetProfile` in `shell.dart`): lowest height keeping the page's header, middle size (where it opens and snaps; GO fits it to the card shown with `PanelSheetScope.fitContent`), never under the status bar; search and traffic are locked at full height. Pages are laid out at least 180 px high and clipped when the sheet is lower (no overflow). Shortcuts: `/` search, `Esc` back.
- **Map** (`core/map/`): one `MainMap` (flutter_map, Plan IGN tiles from the Géoplateforme, no key; inverted in dark mode) behind every page. A page shows things on it by wrapping its content in `MapOverlayScope(overlay: MapOverlay(pins, paths, fit))`; overlays are keyed by route location, the map shows the current one (`routerLocationProvider`). The camera only moves when `fit` changes, and frames it in the part not hidden by the panel.
- **API** (`core/api/`): `models.dart` (freezed models of `/api/v2` and auth), `MobilityApi` (v2 endpoints), `AuthApi`, `api_providers.dart`. `AuthInterceptor` (dio `QueuedInterceptor`) adds the access token, renews it with the refresh token (rotated on each use, so requests wait for a single refresh) and reports a rejected refresh token to `AuthController`. Errors become `ApiException` (message in the app's language).
- **Auth** (`features/auth/`): `AuthController` (`unknown` / `signedIn` / `signedOut`). `TokenStore` keeps the access token in memory and only the refresh token in `flutter_secure_storage`; passwords are never stored.
- **Location** (`core/location/`): `userLocationProvider` (geolocator, null when unavailable, e.g. Linux without GeoClue; `locationIssueProvider` + `fixLocationIssue` offer to turn location on / allow it on phones, retried when the app resumes); `nearbyOriginProvider` falls back to the map center; `nowProvider` ticks every 15 s for "3 min" labels.
- **Features** (`features/`): `home` (search box, nearby departures; `around_screen` = departures around a searched place), `search` (with `?pick=<title>` it chooses a journey start/end and pops a `JourneyPlace`), `journey` (`JourneyRequest` lives in the `/journey?from=&to=&at=&arriveBy=&modes=&wheelchair=&walk=&velib=` URL; new searches get the device's `journeyPreferencesProvider` (wheelchair, walking speed, Vélib, saved from the options sheet); `velib=1` adds the backend's `bike_share` option; `from`/`to` = `here`, a stop area id or `lat,lon`; results by Navitia category; the opened option is passed to `/journey/detail` through `selectedJourneyProvider`, lost on a web reload; `journeyOverlay` draws it on the map), `favorites` (`FavoritesController`: server favorites `/api/v2/me/favorites` with a device copy shown first; home/work/place shortcuts, favorite stops with live departures and lines on the home page, stars on stop and line pages), `search/recent_searches.dart` (last 10 places/lines chosen, device only), `stops` (stop area: lines, departures, walking connections; `timetable_screen.dart` = scheduled timetable `/stops/{id}/timetable?line=&date=`, hours × minutes per direction, letters for other destinations, scrolled to the current hour), `bikes` (Vélib: stations around the home position on the map and in a section, `showBikeStationSheet`, live counts in the Vélib section of a journey detail), `lines` (directions, branches, stop timeline, path on the map, disruptions; vehicles of the direction shown from `/lines/{id}/vehicles` every minute (estimated-timetable quota), moved along their segment between fetches by `vehicleProgress`, placed on the branch path with `BranchPath` and on the stop timeline; tapping one opens `showVehicleSheet`: its next stops with times, delay, platform and mission, followed across fetches by `sameVehicle`), `traffic` (`/traffic` page: badge grid per main mode with severity dots and the disrupted lines; `TrafficSummaryCard` on the home page; `lineSeveritiesProvider` marks disrupted lines in favorites and journey results; `DisruptionList` on line/stop pages, elevator outages grouped, upcoming ones folded), `onboarding` (`/welcome` once per device after the session is known: intro, location, home/work; the flag is read in `main()` before `runApp` so the router redirect stays synchronous). The journey detail shows, per ride, the line's active disruptions and its departures stopping at the alighting stop from when the traveller gets to the boarding stop (`rideOptionsProvider` = `/lines/{id}/rides?after=`) in `RideDepartureList` (`journey/widgets/ride_departures.dart`, Citymapper-like: times at both stops, mission code, destination, platform; the departure taken is raised and scrolled to, unreachable ones faded). Choosing another departure retimes the journey (`journey/journey_retime.dart`, `retimeJourney`: chosen rides, else the planned departure while catchable, else the first one after the previous ride's arrival and the walk; walks follow, waits fill); GO mode uses the same list on every ride card and `GoController.choose` retimes the followed journey from that ride. Data providers are `FutureProvider.autoDispose(.family)`; real-time ones re-fetch every 30 s with a `Timer` + `ref.invalidateSelf` (Riverpod pauses them when not shown).
- `core/platform/live_journey.dart`: system side of GO (Android: foreground service, live notification, alerts, keep screen on through `MainActivity`; web: `browser_web.dart` = Notification and Screen Wake Lock APIs through `dart:js_interop`, conditional import with `browser_stub.dart`). Modal sheets use `useRootNavigator: true`: the pages live in the panel's navigator.
- **Sharing** (`core/platform/share.dart`): links to the web app (`AppConfig.webAppUrl`, `WEB_APP_URL`, default `https://app.guillaumedamiens.com`) for stops, lines and journeys; Android share sheet through `MainActivity`, browser share sheet, else clipboard, else a dialog with the link. A journey link is `/journey/detail?<search>&dep=&lines=` (`Routes.journeyDetailOf`): `sharedJourneyProvider` runs the search again at that time and takes the option with the same lines ("Ma position" is replaced by the journey's start when sharing). Android App Links for that host (`AndroidManifest.xml`, `web/.well-known/assetlinks.json` with the signing certificate's SHA-256, served by the web app's host).
- **Offline** (`core/offline/`): `OfflineCacheInterceptor` keeps the last 60 answers of the read endpoints (no vehicles, rides, Vélib, search) in `LocalStore` and serves them when the server can't be reached; `OfflineBanner` over the map says since when. Cleared at sign-in/sign-out.
- **Language** (`l10n/l10n.dart`): French or English, the device's choice (account menu, sign-in pages) kept in `LocalStore` and read in `main()`, else French when the system is in French and English otherwise. Changing it rebuilds the whole tree (`KeyedSubtree` in `app.dart`) so that `currentL10n` texts follow. Android resources (`values/` English, `values-fr/`) hold the native texts: notification channels, widget placeholders.
- `core/storage/local_store.dart`: small JSON documents in `SharedPreferencesAsync` (favorites copy, recent searches), cleared at sign-in/sign-out so that another account never sees them.
- `main.dart` waits (≤ 3 s) for the Inter font fetched by google_fonts: chips keep sizes measured with the fallback font otherwise.
- `core/widgets/`: `LineBadge` (IDFM look per mode), `DepartureTime`, `AsyncView`.
- **Home screen widget** (Android, `features/home_widget/home_widget_sync.dart` + `NextDepartures.kt`): next departures (clock times) of the first favorite stop, else the closest one, written by `HomeWidgetSync` on the home page (at most once a minute); its refresh button runs `homeWidgetBackgroundCallback` in a background isolate (renews the access token from the stored refresh token, which the app re-reads before each renewal since the rotation revokes reused ones). `MainActivity.kt` also holds the live notification, share and keep-screen-on channel.

## Conventions

- State: Riverpod 3 providers written by hand (no riverpod_generator). Models: freezed + json_serializable.
- No `dart:io` / `Platform` outside platform-specific code: everything must run on the web and desktop.
- User-facing strings in `lib/l10n/app_fr.arb` (template) and `app_en.arb`, generated by gen-l10n into `lib/l10n/generated/` (not committed; `flutter pub get` or `flutter gen-l10n` rebuilds it). Widgets use `context.l10n`; code without a context (formatting helpers, `ApiException`, GO alerts and notification, home screen widget) uses `currentL10n`. Data from IDFM / Navitia (stop names, disruption messages, walking instructions) stays in French. Times from the API are UTC (`Departure.time`), display with `formatClock` / `departureLabel`.
- Stop areas (`IDFM:71264`) and IDFM line ids (`C01371`) everywhere, as in the backend v2 API.
- Accessibility: icon-only buttons get a `tooltip` (it is their screen reader label), tappable map pins a `label`. Layouts must hold with a large system text size (×1.8 checked): fixed row heights go through `MediaQuery.textScalerOf(context).scale(...)`, and crowded rows drop or move secondary items from ×1.3 (departure times, traffic badges, the stop's "Y aller" label, the journey toolbar).
- No automated tests: check with `flutter analyze`, builds and by running the app.
